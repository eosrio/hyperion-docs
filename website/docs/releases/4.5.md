# Hyperion 4.5

Hyperion 4.5 adds explicit protocol-provider boundaries, source-aware ABI/history handling and exact sequence processing while retaining the existing history API families. Use the [upgrade guide](/providers/update/) to preserve your installation's data and configuration.

## History and sequence handling

Preserve uint64 sequence metadata as canonical decimal strings in consumers. Avoid converting these identifiers to JavaScript Number, including in pagination, joins or replay checkpoints. Indexed field semantics and returned JSON representation must remain consistent through the whole client path.

History reads distinguish query/storage failure and missing source authority from a successful empty result. Bounded historical queries and known source ranges make exports and recovery verifiable. Cold action payload hydration is controlled by `api.archives` and the request's `hydrate` option; it does not establish a decoded-field query projection.

## Protocol providers

The default Antelope path remains selected when `settings.protocol` is omitted. Extension providers carry exact profiles and verified component artifacts. Select the package/profile before decoding the chain, and use a controlled restart for executable changes. See [protocol configuration](/extend/protocols/).

ABI/source authority is tied to the relevant source block and action epoch. Missing or conflicting coverage is an explicit error boundary; a latest ABI is insufficient proof. Native genesis admission and source journals preserve the provenance needed by those checks.

## State and extension boundaries

Protocol codecs, contract projections, API domains and database adapters have separate contracts. The portable projection runtime and MongoDB adapter expose scoped initialization, replay and readiness behavior. Existing state collections are not automatically migrated into that adapter or exposed through a new HTTP domain.

Extension projections covered by the core readiness guard return retryable HTTP 503 while unavailable. Unaffected retained history remains a separate serving path. See [state projections](/extend/projections/) for the integration boundary.

A plugin's owner-v2 projection can back five core state routes, including `get_tokens` and `get_top_holders`, once `features.stateful_owner_v2.maximumServingLagBlocks` bounds how far a served view may trail. Projection-backed token responses add `balance`, the exact asset text. The Wire state plugin serves Wire token balances this way. See [plugin-backed core state routes](/extend/projections/#plugin-backed-core-state-routes).

## Operator workflow

Use `config/connections.json` for service endpoints and credentials, and `config/chains/<chain>.config.json` for chain behavior. The CLI validates these paths and settings. PM2 remains the default process manager; supplied systemd units provide an opt-in single-instance API alternative.

Retain existing historical indices and initialize new coverage/state capabilities separately. Reindexing every historical document is not a universal upgrade prerequisite. Verify the data and enabled features you actually serve after an upgrade.

## Compatibility and known limits

The core uses Node 22/24 CI, TypeScript 7.0.2 and Bun 1.4.3 for development checks. Native-module libc requirements and database/server compatibility remain independent of JavaScript package versions. See [component compatibility](compatibility.md).

Wire profiles must match the intended node/contracts/genesis. Installing a profile does not certify arbitrary testnets or every application contract. Delta archive hydration and automatic portable-state HTTP migration are not end-to-end core capabilities. These are concrete capability limits, not reasons to substitute successful empty results.
